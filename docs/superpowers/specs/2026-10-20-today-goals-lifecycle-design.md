# 今日の目標・進捗アイコン・延期・完了後の整理 設計

2026-10-20 / Ichi の「Flick アプリ改善指示書」と質問への回答をもとに作成。

## 1. ねらい
- **タスク全体の完了**と**今日予定していた分の完了**を分ける。大きなタスクを予定どおり進めた日に「やりきれなかった」と感じさせない。
- 「未着手・進行中・完了」（タスクの状態）と「今日やる・延期」（日単位の予定）は別の概念として扱う。
- 既存の見た目・操作感（白ベースのリキッドグラス、フリック）を保ち、画面遷移や操作を増やさない。

### やらないこと（非目標）
- サブタスクの入れ子（サブタスクのサブタスク）
- 複数日にまたがる計画（明日の目標の先取り設定など）
- 全サブタスク完了で親を**自動で**完了にすること（提案だけする）

### 失敗とみなすもの（反目標）
- 延期・目標変更・自動整理で、タスク本体やサブタスクの進捗が消える／戻る
- 既存のタスク・期限・進捗・添付が失われる
- 7 日・30 日の自動処理がアーカイブ済みのタスクに触れる

## 2. 現状（コードを読んで分かったこと）
- サブタスクも `tasks` テーブルの 1 行（`parent_id` 付き）。**各行に `today` 列がすでにある**（親だけが使用中）。
- 進行中の丸アイコンは、色が半分塗られた固定の円（`.dot.doing` の conic-gradient 50%）。
- 期限を入れるだけで状態を変えるコードは**ない**。Ichi の回答: 詳細画面で日付を選んだとき起きた → iPhone で日付の選択を閉じたタップが、すぐ上の状態切り替え「進行中」に当たっていると判断（明確な不具合として修正する）。
- 今の「アーカイブ」（`archived_at`）は実質「削除」: 未着手の左フリック、サブタスクの ×、詳細下部のボタンで使われ、あとから見る画面がない。GET /api/tasks はアーカイブ済みを返さない。

## 3. データ（migration 0006）
| 列 | 意味 |
|---|---|
| `status` | 既存のまま todo / doing / done |
| `today`（既存） | 親: 今日やる日。**サブタスク: 今日の目標にした日**（`today === 今日` なら今日の目標） |
| `done_at`（新） | 完了になった時刻。完了でなくなったら null |
| `archived_at`（既存・意味変更） | **アーカイブに保存した時刻**。保存は無期限 |
| `trashed_at`（新） | ゴミ箱に入れた時刻 |

- 新テーブル `deleted_tasks(id, user_id, deleted_at)`: 完全削除した id の記録。古い端末の送信待ち（outbox）が完全削除したタスクを復活させないよう、PUT はここにある id を拒否する（410）。
- 既存データの移行:
  - 既存の `archived_at` 付きの行（これまでの削除）→ `trashed_at = 移行時刻`、`archived_at = null`（30 日間はゴミ箱から戻せる）（決定: Claude）
  - 既存の完了タスク → `done_at = 移行時刻`（移行直後に消えないよう、7 日は移行日から数える）（決定: Claude）
- 古いクライアントが新しい列を送らない場合、サーバーはその列の既存値を保つ。
- GET /api/tasks はゴミ箱・アーカイブも含めて返す（画面側で振り分け）。

## 4. 今日の目標（指示書 1）
- **設定のしかた**
  - 詳細画面: タスクが今日に入っているとき、各サブタスクの行に「今日」トグル（太陽アイコン）が出る。タップで今日の目標に入れる／外す。いつでも変更可。
  - 「今日やる」を押した直後、未完了のサブタスクがあれば「今日やる分をタップ」の案内を出す。
  - 朝の選択画面: サブタスクのあるタスクを選ぶと、その下に未完了サブタスクが開き、同じトグルで選べる。（決定: Claude）
  - 1 つずつ選ぶ方式（「ここまで」の範囲選択ではない）。例の「資料収集・構成作成」も 2 回のタップで設定できる。（決定: Claude）
- **見た目**: 目標のサブタスクは行の左に淡い色の帯と太陽アイコン。サブタスク見出しに「全体 2/4」と「今日 1/2」を別々に出す。
- **達成の判定**
  - 目標のサブタスクがある: それが全部完了 → 今日の目標達成（親が未完了でも）
  - 目標がない（サブタスクなし・未設定）: 従来どおり親タスクの完了で達成
- **今日画面**: 上部のバーと数字を「今日の目標 X / Y 達成」に変える。カードには「今日 1/2」チップ。達成したカードは「今日分 完了」の表示になって下に移る（完了タスクと同じ扱い）。全部達成したら上部バーが軽く光る。
- 日付が変わると古い目標は自然に無効（サブタスクの `today` が今日でなくなる）。進捗は残る。

## 5. 進捗アイコン（指示書 2）
- 進行中の丸の塗りを「完了サブタスク数 ÷ 全サブタスク数」にする（0/25/50/75/100%）。塗りはばねアニメーションで増減。
- 一覧・今日画面・詳細のどこでも同じ。サブタスクの追加・削除（ゴミ箱）・完了取り消しで即再計算（ゴミ箱のサブタスクは数えない）。
- サブタスクがない進行中タスクは、今と同じ半分塗り（決定: Claude）。
- これは**全体の**進捗。今日の目標の達成率は表さない。

## 6. 延期（指示書 3）
- 詳細画面: 今日に入っていない → 「今日やるに追加」。入っている → 「明日以降に延期」。
- 延期 = 親とそのサブタスクの `today` を外すだけ。状態・完了済みサブタスク・進捗は一切変えない。トースト「延期しました［元に戻す］」（目標も含めて戻る）。
- 今日画面の未着手カードの左フリック「今日から外す」も「延期」に名前をそろえる（動作は同じ）。
- 期限が今日以前で自動的に今日に入っているタスクは、今のとおり延期ボタンの代わりに説明を出す。

## 7. 進行中への自動移動（指示書 4）
- 期限は状態の判定に使わない（今もそうなっている）。
- 未着手のタスクのサブタスクが 1 つ完了したら、親を進行中にする。今日画面では並び位置を保つ。
- サブタスクがないタスクは、フリックか詳細の状態ボタンで進行中にする（それが「着手した」という操作）。（決定: Claude）
- 完了取り消しで自動的に未着手へは戻さない。
- サブタスクが全部完了したら「すべて完了。タスクも完了にする？［完了にする］」と提案するだけ。
- 既存の進行中タスクはそのまま。
- **不具合修正**: 詳細画面で日付の入力が変わった・閉じた直後 0.6 秒は、状態切り替えのタップを無視する。

## 8. 完了・アーカイブ・ゴミ箱（指示書 5）
状態遷移:
```
未着手 → 進行中 → 完了 ─(右フリック/ボタン)→ アーカイブ ─→ ゴミ箱 ─→ 完全削除
完了 ─(左フリック/ボタン)→ 進行中に戻す
アーカイブ ─→ 進行中に戻す
完了 ─(7 日・未アーカイブ)→ ゴミ箱 ─(30 日)→ 完全削除
未着手の左フリック / サブタスクの × / 詳細の削除ボタン → ゴミ箱（Ichi 回答）
```
- **完了リスト**: 左フリック「進行中に戻す」、右フリック「アーカイブに保存」。詳細画面では完了タスクに 3 つの状態ボタンの代わりに「進行中に戻す」「アーカイブに保存」を出す。今日画面では完了カードの右フリックは無効のまま（誤操作防止）。
- **アーカイブ・ゴミ箱の画面**: 右上のメニューに「アーカイブ」「ゴミ箱」（件数付き）を追加し、下から出るシートで開く（Ichi 回答）。行は見えるボタンで操作する（隠れたフリックにしない）。（決定: Claude）
  - アーカイブ: 各行に「進行中に戻す」「ゴミ箱へ」。無期限保存。
  - ゴミ箱: 各行に「元に戻す」「完全に削除」（2 回タップで確定、添付と同じ）、下に「ゴミ箱を空にする」（2 回タップ）と「30 日で自動的に完全削除されます」。1 件ずつ消したサブタスクは「親タスク名 › サブタスク名」で並ぶ。
  - 元に戻す先: ゴミ箱に入る前の場所（アーカイブから来たものはアーカイブ、完了で 7 日たったものは完了リスト。後者は `done_at` を今にして、すぐまた消えないようにする）。
- **自動処理**: Workers の Cron（毎日 04:00 JST = 19:00 UTC、無料）
  - `done_at` から 7 日たった完了タスク（アーカイブ・ゴミ箱でないもの）とそのサブタスク → ゴミ箱
  - `trashed_at` から 30 日たったもの → 完全削除（行・添付の KV と D1・要約）、`deleted_tasks` に記録
  - 変更した行は `updated_at` を進め、各端末の次回同期で反映される
- **完全削除 API**: `DELETE /api/tasks/:id`（ゴミ箱にあるものだけ。サブタスクと添付も消す）、`POST /api/tasks/trash/empty`。

## 9. 共通の約束
- 状態変更と今日の操作は互いに相手の値を変えない（延期は status を、状態変更は today を触らない）。
- サブタスクの変更は一覧・進捗アイコン・今日画面に即反映（ストアから計算するので自然にそうなる）。
- 他人のタスクには触れない（全 SQL を user_id で絞る）。
- 親と一緒にゴミ箱・アーカイブに入ったサブタスクは、親と一緒に戻る（同じ時刻で判定。今の archive/restore と同じ考え方）。
- AI（今日のおすすめ・サブタスク提案の添付参照）と件数バッジは、アーカイブ・ゴミ箱のタスクを含めない。

## 10. テスト
- API: 新しい列の保存と古いクライアント互換、移行、Cron の 7 日／30 日（時刻を注入）とアーカイブ除外、完全削除と添付削除、削除済み id の PUT 拒否、他人のタスク。
- 画面（Playwright）: 今日の目標の設定→達成表示（例: レポート 4 件中 2 件）、進捗アイコンの 0→25→50%、延期で進捗が残る、サブタスク完了で進行中へ、期限を入れても未着手のまま、完了→アーカイブ→ゴミ箱→元に戻す／完全削除、未着手の左フリックがゴミ箱へ。
- 実操作: アプリ内ブラウザでローカル → 本番。見つかった明確な不具合はその場で直して再テスト。

## 11. 実装者に任せること
- 太陽トグル・帯・チップの細かな色と大きさ（既存トークンから選ぶ）
- シートの並び順（新しい順）と件数表示の位置
- Cron の時刻ずれ吸収（境界付近の扱い）
