# 「進行中」の廃止・並び替え・検索 設計

2026-10-21 / Ichi の指示書（2. 進行中の廃止、7.〜11. 並び替え・検索）と質問への回答をもとに作成。
前回の設計 `2026-10-20-today-goals-lifecycle-design.md` のうち「進行中」に関わる部分（5・7 章、8 章の「進行中に戻す」）はこの文書で置き換える。

## 1. ねらい
- タスクの状態は「未完了」「完了」の 2 つだけにする。「今日」は状態ではなく「今日取り組む」という印。
- 朝に「今日やる」を選ぶとき、優先度の高いタスクをすぐ見つけられるようにする（並び替え・検索）。
- 見た目と操作感は今の Flick のまま。情報を増やしすぎない。未完了を失敗として強調しない。

### やらないこと
- AI による意味検索（今は不要と指示あり）
- 「完了」タブの操作の変更（今のまま）
- 「今日」タブへの並び替え・検索（指示の対象外）

### 失敗とみなすもの
- 移行でサブタスク・メモ・期限・作成日時・今日の目標・添付が失われる
- 並び替えや検索で、選んだタスク（チェック）が外れる／データが書き換わる
- タップした瞬間に並びが動いて、押したいものを押し損ねる

## 2. 状態を 2 つに（指示書 2）
- `todo`（表示名「未完了」）と `done`（「完了」）のみ。`STATUSES = ["todo", "done"]`。
- **移行（migration 0007）**: `status = 'doing'` の行を `todo` にし、`updated_at` を進める。他の列は触らない。
- 古い端末（更新前のアプリ）が `doing` を送ってきたら、サーバーは `todo` として保存する。
- **タブ**: 「今日」「タスク」「完了」。
  - タスク = 未完了のすべてのタスク（今日に入っているものも含む。カードに「今日」チップ）
  - 完了 = 完了したタスク（今のまま）
- **フリック**（Ichi 回答: 右はそのまま完了）
  - タスク・今日タブ: 右 = 完了。左 = タスクタブではゴミ箱、今日タブでは延期（今のまま）
  - 完了タブ: 右 = アーカイブに保存、左 = 「未完了に戻す」
- **詳細画面**: 未完了のときは「未完了 / 完了」の 2 つの切り替え。完了のときは「未完了に戻す」「アーカイブに保存」。日付操作直後 0.6 秒のタップ無視は残す。
- **進捗アイコン**: 未完了のタスクは、完了したサブタスクがあればオレンジの扇形で完了率を表示（1/4 なら 25%）。サブタスクがない・まだ 0 件なら空の丸。完了は今の緑のチェック。
- サブタスク完了で親を自動で動かす処理と「進行中にしました」の表示はなくす。全サブタスク完了時の「タスクも完了にする？」の提案は残す。
- アーカイブの「進行中に戻す」→「未完了に戻す」。
- AI の今日のおすすめ: 「進行中」の代わりに「着手済み（サブタスク a/b 完了）」を材料として渡す。

## 3. 並び替え（指示書 7・10）
3 つの方式。純粋な関数 `sortTasks(list, mode, ctx)` 1 つで、選択画面とタスクタブの両方が使う。データは一切変えない（表示順だけ）。

- **基準の日付**: アプリの「今日」（04:00 で切り替わる端末のローカル日付）。期限までの日数 = 期限日 − 今日（日単位）。（決定: Claude。「期限が今日まで」の判定と合わせるため）
- **着手済み**: ゴミ箱・アーカイブでないサブタスクのうち 1 つ以上が完了。
- **おすすめ順**（初期設定）
  1. 期限が 3 日以内（期限切れ・今日・明日・2 日後・3 日後）: 期限の古い順
  2. 着手済み（1 に入らないもの）: 期限の近い順、期限なしは後ろ
  3. 期限が 4〜7 日後（未着手）: 期限の近い順
  4. その他（8 日以上先・期限なし）: 期限ありを近い順に先、期限なしを後
- **期限順**: 期限切れ（古い順）→ 今日 → 明日以降（近い順）→ 期限なし。進捗は見ない。
- **追加順**: 作成日時の新しい順。
- **同順位**: 作成日時の新しい順 → さらに同じならタスク ID 順。
- 日付が変わる・期限を変える・サブタスクを完了すると自動で並び直す（画面は毎回ストアから計算するので自然にそうなる）。
- **設定の保存**: 選択画面とタスクタブで別々に、この端末に保存（ブラウザの保存領域）。初期値は 選択画面 = おすすめ順、タスクタブ = 追加順（Ichi 回答）。

## 4. 検索（指示書 8・9）
- 対象: タスク名とメモ。部分一致。入力のたびに更新。英数字の大文字・小文字を区別しない（全角・半角の英数字も同じ扱いにする: 決定 Claude）。
- どちらかに一致すれば表示。× ボタンで消せる。0 件なら「一致するタスクがありません」。
- 順序: 表示できるタスク → 検索で絞る → 並び替え → 表示。
- 並び替えを変えても検索語は残る。検索・並び替えを変えても選択（チェック）は残る。
- 検索語は保存しない（画面を閉じれば消える）。（決定: Claude）

## 5. 画面
- **共通の検索・並び替えバー**（`ListTools`）: 1 行に「🔍 タスク名・メモを検索」の欄と「おすすめ順 ▾」の小さなボタン。ボタンを押すと 3 つの選択肢が小さなメニューで出て、選択中にチェック。選ぶと即並び替え、メニューは閉じる。画面遷移なし。
- **朝の選択画面**（Ichi 回答: 1 本のリスト）
  - 区分け（選択中／昨日の残り／期限が今日まで／そのほか）をやめて 1 本のリストに。完了タスクは含めない。
  - 選んだものはチェック。期限が今日までのものはチェック済み・外せない（今のまま）に「自動」ラベル。昨日の残りは「昨日の残り」ラベル（初期チェックも今のまま）。
  - タップしても並びは動かない（チェックの有無で並べ替えない）。
  - 今日の目標（サブタスク選択）の開き方は今のまま。
- **タスクタブ**: 一覧の上に同じバー。検索中は一致するものだけ表示。
- 今日・完了タブは変更なし。

## 6. テスト
- API: `doing` を送ると `todo` で保存される、移行で `doing` が `todo` になり他の列は保たれる。
- 並び替えの単体テスト: 指示書の 3 方式・同順位・境界（3 日後／4 日後、7 日後／8 日後、期限切れの古い順、着手済みの扱い）。
- 画面: タブが 3 つ、右フリックで完了、完了タブの左で未完了に戻る、進捗アイコン、選択画面の検索（タスク名・メモ・大文字小文字・0 件・クリア）と並び替え（即時・保存・再表示で維持・選択が残る）、タスクタブの検索と並び替え。
- 実操作: アプリ内ブラウザでローカル → 本番。明確な不具合はその場で直して再テスト。

## 7. 実装者に任せること
- バーとメニューの細かな見た目（既存のガラス調・トークンで）
- 「自動」「昨日の残り」ラベルの色
